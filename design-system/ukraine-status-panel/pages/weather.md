# Погода: правила экрана и пиктограмм

Дополнение к MASTER.md, роадмапу и принятым правилам M3.
Основание: WEATHER_REFERENCES.md, просмотр Figma и UI UX Pro Max.
Применяется к будущему развитию погодных экранов; само по себе наличие
этого файла не означает, что новый экран установлен на устройство.

## Информация и источники

Показывать выбранный город, его страну, текущую температуру, состояние,
ощущаемую температуру, наружную влажность, ветер и свежесть данных.
Четыре карточки прогноза содержат настоящую дату, состояние, максимум/
минимум температуры и вероятность всех осадков. Процент относится
к вероятности; миллиметры — отдельная величина.

При отсутствии текущих данных вместо чисел стоят обозначения отсутствия
и понятный статус. После смены города предыдущие показания очищаются.
При временном отказе источника для того же города последняя подтверждённая
погода может оставаться с признаком ошибки/устаревания.

Комнатная температура и влажность имеют отдельную подпись и источник
SHT4x. Отсутствующий модуль обозначается «Не подключён». Прогноз нельзя
выдавать за историю измерений. История M6 хранит реальные отсчёты,
временные отметки и пропуски в ограниченном буфере.

Текущая типизированная модель содержит 24 почасовые точки и 7 дней, UV,
восход/закат, давление, направление/порывы ветра и количество осадков.
Secondary hourly details независимы: отсутствие одного показателя не удаляет
core-hour, а отображается как `--`; настоящий ноль остаётся нулём. Пустая
карточка UV и вымышленная фаза Луны не нужны.

## Структура LCD 1024×600

Сохранить верхнюю полосу статуса региона и видимую навигацию по умолчанию.
В содержимом: большая карточка текущей погоды слева, компактные показатели
справа, четыре одинаковые карточки прогноза снизу. Не переносить боковую
панель Figma с маленькими кнопками без подписей на сенсорный LCD.

Основной текст 20–22 px, вторичные подписи около 18 px. Названия городов
должны иметь ограниченную ширину и перенос/сокращение, не вытесняя
температуру. Предпочитать меньше показателей на экране уменьшению шрифта.
Управление — кнопки высотой 48–56 px, с понятными подписями.

Полноэкранный режим использует тот же набор данных и страниц. После
скрытия навигации место получает содержимое. Свайп и локальный выход
реализуются общим механизмом M4, независимо от погодного виджета.

## Пиктограммы

Одна таблица WMO → семантическая группа в `include/usp_weather_codes.h`
используется транспортом, текстом и компактными иконками. Неизвестный
код означает неизвестное состояние. Отсутствующие данные не получают
солнечную пиктограмму или значение 0 °C.

Для нового набора нужны Clear day/night, Partly cloudy day/night,
Overcast, Fog, Drizzle, Rain, Snow, Showers, Snow showers, Thunderstorm
и Unknown. Для текущих условий день/ночь берётся из `is_day` источника;
суточный прогноз использует согласованную дневную форму. Декоративная
луна не должна изображать измеренную фазу Луны.

Формы имеют одинаковую толщину линий, пропорции и размеры 24/32/64/96 px.
Рядом остаётся текстовое состояние. Иконки поставляются локально,
без emoji, CDN, удалённых шрифтов и Lottie. Для LVGL заранее готовятся
прозрачные маски/bitmap выбранного размера; для Web — локальные SVG.
Перед выбором формата измерить стоимость декодирования и перерисовки.
В .220 встроенный Web JS занимает 32678 из 32768 байт: остаток 90 байт.
Новый набор изображений требует отдельного расчёта упаковки и бюджета;
вставлять его в текущий JavaScript без пересмотра ресурсов нельзя.

Монохромная форма сохраняет силуэты солнца, облака, осадков, тумана,
снега и грозы. Цвет не должен быть единственным различием.
Предусмотреть высокий контраст на тёмном и светлом фоне.

В каталоге иконок UI UX Pro Max проверенного погодного набора не найдено
после двух запросов. Эти правила — общие рекомендации и самостоятельная
адаптация изученных референсов. Из UX-каталога применима рекомендация
Empty States: объяснять отсутствие содержимого и доступное действие.

## Оформление и работа с данными

Непрозрачные тёмные поверхности M3, локальные шрифты и минимальные эффекты.
Свежесть обозначается текстом и временем, дополнительно цветом.
Показатель ветра содержит единицу km/h/км/ч; порыв и направление добавляются
только при наличии собственных полей. Вероятность и количество осадков
не смешиваются на одном неподписанном графике.

Почасовой график — последующее расширение. Нужны UTC-время точки,
часовой пояс города, ограничение количества точек, явные единицы,
разрывы при отсутствии значений и отсутствие вымышленных нулей.
Обновляется изменившийся блок; работа скрытой страницы откладывается.
Сохранить проверенный resident Home fast-first-paint из M2.

При расширении модели разделить время измерения источника, время получения
и результат последнего запроса. Сейчас срок устаревания считается от
получения ответа, а строка времени источника выводится отдельно. Для
почасовых рядов нужны проверенные UTC-метки: один только успешный HTTP
не подтверждает, что поставщик прислал недавние измерения.

Перед рисованием собирать один согласованный снимок всех отображаемых
полей. Ошибка обновления, отсутствие данных и устаревший снимок — разные
состояния; сообщение должно объяснять, какое из них наблюдается.

## Приёмка следующего изменения экрана

- UA/RU/EN, длинное имя города, отрицательная температура.
- День/ночь, все WMO-группы, Unknown и отсутствие данных.
- Старый ответ после смены города и поиска не меняет новый выбор.
- Сбой источника, устаревание, частичный прогноз, отсутствие SHT4x.
- Кнопки и полноэкранный режим, локальный выход, отсутствие конфликта тапа
  и свайпа; отдельная проверка настоящего пальцевого ввода.
- Web 320/375/768/1024/1440, клавиатура, фокус и увеличение текста.
- Бюджеты встроенных ресурсов, память, UART и повторный быстрый Home.

Порядок: исправления достоверности .219 и HTTPS .220 → M4 навигация → отдельный
проверяемый погодный экран/пиктограммы → часы M5 и история M6.
