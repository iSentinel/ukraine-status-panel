# Исполняемые проверки производственного кода

Запуск из корня проекта на CT106:

```sh
/root/config/.qa-venv/bin/python tests/semantic-production-native.py
```

Обычный запуск проверяет пять исполняемых программ с ASan/UBSan. Он входит
в `scripts/run-regression.sh`. Компиляция выполняется для сервера, образ
прошивки не создаётся; соединений с панелью нет.

Для проверки способности обнаружить ошибку укажите новый каталог:

```sh
/root/config/.qa-venv/bin/python tests/semantic-production-native.py \
  --mutation-probes --output artifacts/my-semantic-probes
```

Программа копирует только нужные исходники и изменяет копии в этом каталоге.
Она не перезаписывает существующий каталог результатов. Для каждой проверки
сохраняются команда компиляции, исходники, журнал компиляции и журнал запуска.
Ошибка компиляции не считается обнаружением мутации: изменённая программа
должна успешно собраться и остановиться на проверке ожидаемого поведения.

Проверяемые контракты:

- OTA pipeline: полный производственный C++, порядок порций, смещения,
  размер, очистка и ошибки; операции физической flash заменены в тесте.
- OTA guard: точный метод `add_writer_dry_run_chunk`, без переписывания
  условий; вызов SHA заменён счётчиком. Криптография здесь не проверяется.
- SHT4x: точные выражения влажности для всех 65536 значений, независимое
  ожидаемое значение и обязательное ограничение 0–100%.
- Room chart: полный заголовок, настоящий RoomHistory, границы 599/600/601 с,
  разрыв 900 с, сегменты и сохранение последних 12 серий. Вызовы LVGL
  заменены пустыми функциями; внешний вид дисплея здесь не проверяется.
- Outage calendar: полный заголовок, сегодня/завтра, смена года, високосный
  день и даты перехода времени. Отдельный существующий
  `outage-calendar-native.py` проверяет производственные методы клиента.

Шесть мутаций охватывают четыре семейства исторических ошибок E-T2:
смещение OTA +1 (pipeline и guard), отсутствие ограничения и неверный
коэффициент SHT4x, BREAK_SECONDS ×10 и сдвиг календарного дня.
Исходный обзор не сохраняет точный patch каждой старой мутации, поэтому
эти явно записанные варианты служат воспроизводимыми проверками семейств.

Это проверка программных контрактов на сервере. Она не означает аппаратную
приёмку, полное покрытие всех модулей OTA или достижение целевого процентного
соотношения видов тестов. Полный production fingerprint проверяется отдельно.
