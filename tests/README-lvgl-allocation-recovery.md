# Восстановление выделения памяти LVGL

Проверка без панели:

```sh
/root/config/.qa-venv/bin/python tests/lvgl-allocation-recovery-native.py
```

Для сравнения с изолированной копией:

```sh
/root/config/.qa-venv/bin/python tests/lvgl-allocation-recovery-native.py \
  --source artifacts/my-copy.cpp --output artifacts/my-allocation-proof
```

Скрипт извлекает настоящие ESP32-функции malloc/realloc/free, выделение
рисующего буфера и монитор памяти. Их ветви не переписываются. Внешние
heap_caps_* функции заменяются управляемой моделью памяти и реальными
буферами сервера. ASan/UBSan проверяют доступ и освобождение.

После временного отказа следующая операция снова обязана запросить SPIRAM.
Проверяются обычные и явно внутренние рисующие буферы, выравнивание,
сохранность старых байтов при неудачном realloc, освобождение при размере0,
пустая статистика и1000 циклов отказа/восстановления.

Тест доказывает выбор capability flags и порядок вызовов производственного
кода. Общий MALLOC_CAP_8BIT не гарантирует физическое размещение во
внутренней RAM: окончательный выбор делает ESP-IDF. Здесь не проверяются
реальные heap pressure, задержки или аппаратное поведение PSRAM.

Исходный код и панель не меняются; --output допускает только новый каталог
в artifacts. Код возврата1 после успешной компиляции означает найденную
ошибку поведения. Ошибка компиляции сохраняется отдельно и не считается
воспроизведённым дефектом.
