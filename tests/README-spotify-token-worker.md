# Проверка фоновой задачи Spotify

Запуск всех восьми случаев: python3 tests/spotify-token-worker-native.py. Для исследования гонок: --case binding --repeat 100. Нужны g++, loguru и установленный pinned ArduinoJson 7.4.3. Код production компилируется с ASAN/UBSAN, сетевые/RTOS вызовы заменены host fixtures. Ошибки компилятора и assertions выводятся в журнал.

GET status законно отвечает503 busy при занятости mutex; await_status повторяет только чтение с ограничением времени. Проверочные POST выполняются ровно один раз на явной границе шага worker. Отмена во время заблокированного HTTPS по-прежнему отправляется без паузы worker и проверяет реальную конкурентность. После освобождения HTTPS тест ждёт границы завершённого шага, затем проверяет отсутствие подключения и idle. Отдельный busy_status принудительно занимает настоящий state mutex другим host thread: ожидается503, затем восстановление GET. Производственные mutex, HTTP и scheduler код не меняются. Аппаратные или настоящие TLS проверки не заявляются.

Счётчик HTTP отмечает начало запроса. В проверке Player 401 фиктивные часы и ответ меняются только после завершённого шага: иначе время следующего опроса может сдвинуться вместе с ещё выполняющимся первым запросом. Проверяется также освобождение обоих HTTP клиентов.

Восьмой случай --case artwork-binding проверяет настоящий worker→CDN adapter→JPEG→два кадра и отмену GET. HTTPS заменён fixture; реальные provider/device не вызываются.
