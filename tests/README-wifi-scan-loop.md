# Основной цикл поиска Wi-Fi

Основной loop не ждёт блокировку ответа HTTP: занятое состояние пропускается до следующего прохода. После освобождения запуск происходит один раз и сохраняет задержку250мс. Остальные вызовы lock сохраняют предел100мс; обработчик результатов поиска не переведён на иной механизм этим изменением.

Проверка: /root/config/.qa-venv/bin/python3 tests/wifi-scan-loop-native.py

Параметры: --help и --compiler NAME. Выполняются реальные loop/lock/unlock; декларация lock и задержка берутся из текущего заголовка. RTOS semaphore/radio заменены зависимостями. Проверяются нулевое ожидание loop при contention, default100 для других вызовов, defer, wrap, null и однократный start. Это не измерение задержки на физической панели и не реальное сканирование.

Этот loop-only тест отключает наличие готовых результатов. Реальные callback/collector/JSON/publisher проверяет tests/wifi-scan-results-native.py.

Управление ускоренным режимом Wi-Fi и отказ радио проверяются отдельно
в README-wifi-scan-power.md; здесь эти зависимости заменены для изоляции.
