# Полноэкранная карта с готовым RGB565 изображением
Геометрия, цвета и обработка выбора региона сохранены.
Генератор scripts/generate-fullscreen-cache-assets.py --check сверяет воспроизводимость.
tests/fullscreen-cache-equivalence.py компилирует настоящий C++ renderer с g++:
96 вариантов всех палитр/состояний и отдельных регионов сравниваются побайтно
с прежними масками и контуром. Изображение: 858x488, 837408 байт PSRAM.
При нехватке PSRAM используются прежние 25 масок и42части контура.
Они скрываются только после успешного создания нового изображения.
Маркер Киева остаётся поверх, поверхность касания и геометрия не меняются.

FULLSCREEN_CACHE_PRESENT измеряет от начала подготовки обновления карты
до REFR_READY после RENDER_START на видимой странице. Native flush wait
завершается до этого события. Это не время всей страницы: заголовки и
источники могут обновляться отдельно. Нужна отдельная оценка полного перехода.
Новый буфер выделяется один раз, принадлежит singleton до перезагрузки;
повторное открытие страницы не выделяет память снова.
Не запускать аппаратную проверку общих настроек без журнала восстановления:
старый shared-settings probe может выйти до возврата группы при потере API-ответа.

## Ограниченная подготовка первого кадра .286
Первый кадр собирается по4096 пикселей с паузой1мс между шагами.
Изображение скрыто до полной готовности; исходные маски и прежний резервный
путь сохраняются. Ссылки на67 объектов копируются, а не удерживаются через
временный массив вызывающего кода. Новые данные перезапускают подготовку.
Обычное обновление готового кэша сохраняет прежнюю синхронную семантику.
fullscreen-cold-native.py сравнивает23 набора с захваченным старым renderer,
проверяет бюджет/границы/смену данных и жизненный цикл с подменой LVGL,
PSRAM и часов. Это не доказательство времени на ESP32.
FULLSCREEN_CACHE_COLD_BEGIN/READY покажут setup/max_slice/elapsed на панели.
