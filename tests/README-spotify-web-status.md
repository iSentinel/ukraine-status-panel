# Spotify: состояние входа в Web UI (.339)

Основная страница панели получила отдельную вкладку Spotify.
В ней видны состояние входа и готовность защищённого хранилища сессии.
«Обновить состояние» выполняет только локальный запрос чтения.
«Управлять входом» открывает существующую защищённую страницу авторизации.
При недоступности запроса показано сообщение об ошибке без зависшего ожидания.
Поля приложения и токены не выводятся в этой вкладке.

## Проверка без устройства и аккаунта

QA Python tests/spotify-web-status-static.py проверяет отдельную вкладку,
локальный GET и отсутствие отправки настроек/токенов.
Node tests/spotify-web-status-browser.cjs --script
firmware/webui/usp-web-ui.js запускает18 сценариев UA/RU/EN:
connected/reauth,401, некорректный JSON, обрыв связи, слишком большой ответ,
явное обновление и переход к входу. Все ответы подставные.
Повторить с firmware/webui/usp-web-ui.src.js для читаемых исходников.
Нужны локальные зависимости Playwright из tools/web-ui и Chromium;
PLAYWRIGHT_BROWSERS_PATH задаёт каталог установленных браузеров.

Проверки геометрии, клавиатуры и контраста включают девять вкладок.
Новый тест входит в scripts/run-regression.sh при USP_RUN_BROWSER=1.
Эти результаты не подтверждают работу новой версии на физической панели.
Вход и реальные команды Spotify выполняет пользователь явно.
