# Запрос ускоренного режима Wi-Fi при поиске сетей

Запуск: QA Python с loguru, ESPHOME_BIN с закреплённой версией ESPHome:
wifi-scan-power-native.py --help или без аргументов. --esphome-root позволяет
проверить фактические framework sources из generated build.

Двенадцать настоящих методов компонента работают с заменой часов, блокировки
и драйвера. Проверяются совпадение завершения и нового HTTP-запроса,
занятая блокировка, поздний первый проход, таймаут и немедленный повтор,
ошибка получения режима, отказ запуска радио, устаревший отказ, переполнение
счётчика и 300 повторных запросов. Проверяется также сборка без поддержки
runtime power save. Нативный код исполняется с ASAN/UBSAN.

HTTP только меняет защищённое состояние. Основной цикл владеет запросом
ускоренного режима и даёт штатному циклу Wi-Fi применить его до запуска радио.
Отказ радио публикуется после try-lock на следующем проходе; устаревший отказ
не изменяет новый запрос. Номер запроса не меняет внешний JSON.

Проверка читает настоящие request/release/main-loop методы закреплённого
framework и запрещает незамеченное изменение этого контракта.
Тест не запускает реальный поиск, не меняет сеть и не измеряет аппаратные
задержки. Сборка для ESP32 и отдельная аппаратная приёмка обязательны.

С .315 общий helper проверяет прежний таймаут15000мс под той же блокировкой
и в HTTP, и в основном цикле. Дополнительно: отсутствие HTTP после старта,
expired pending, занятая блокировка, точная граница, wrap и поздний результат.
Публикация выполняется настоящим publish_results_, с реальной структурой
записи и MAX_NETWORKS из заголовка, без модели обработчика публикации.
Поздние результаты не переводят завершённый поиск в READY.
