# Проверка LCD-навигации

lcd-navigation-static.py проверяет доступность шести пунктов, размеры
и промежутки кнопок, место для содержимого и сохранение TLS-конфигурации.
Она входит в обычную локальную регрессию.

lcd-navigation-live-probe.py --address 192.0.2.208 --uart-log PATH

Запускать после сверки установленной версии и начала UART 460800.
Проверка активирует настоящие callbacks кнопок меню и независимо читает
текущую страницу по UART. Настройки и выбранный город не меняются.
Это проверка кода на панели через Native API, а не касание настоящим пальцем.

Сначала сохраняется и принимается исправление видимого меню .221.
Полноэкранный режим, сохранение режима, подавление тапа после свайпа
и локальный выход — следующий отдельный набор M4.

## Проверка контроллера с настоящим LVGL

    python3 tests/lcd-navigation-lvgl-native.py --lvgl-root /path/to/lvgl-9.5.0

Здесь используется та же библиотека LVGL, что в production build, но обычный
процесс на сервере. По умолчанию включены AddressSanitizer и UndefinedBehaviorSanitizer.
Проверяются две области с одинаковым выходящим за границы содержимым:
обычная обрезанная карточка должна принимать свайп, настоящая прокрутка — нет.
Так воспроизводится и предотвращается ошибка блокировки жестов.

Путь можно передать через USP_LVGL_ROOT для полной регрессии.
USP_LVGL_BUILD_DIR или --build-dir сохраняет журналы; каталог должен быть новым.
Без пути к LVGL полная регрессия явно пропускает эту дополнительную проверку.
--cmake и --ninja позволяют указать существующие инструменты; установки нет.
Проверка не доказывает работу физического сенсора GT911 или касаний пальцем.

## Чтение версии перед обновлением и после него

    python3 tests/device-identity-readback.py --address 192.0.2.208 --expected 0.115.228-dev --output /tmp/panel-identity.json

Скрипт только читает имя, версию и время сборки. Ключи и сетевые пароли в файл
не записываются. Для следующего кандидата укажите ожидаемую версию явно.

### Диагностика реального касания (.229)

По умолчанию запись выключена. Действие Native API
`usp_qa_navigation_trace(seconds)` включает её на срок от1 до180 секунд;
ноль выключает. UART460800 сохраняет отдельные сводки GT911 и LVGL:
начало/конец, длительность, число обновлений, блокировку, распознанное действие.
Координаты не меняют решение обработчика. Проверка на компьютере покрывает
обычный таймерный ввод, созданный до attach, сохранение координат при release,
удержание header, выключенную по умолчанию запись и автоматическое истечение.
Это модель, а не доказательство работы пальцем на GT911.

### Ручное листание по кругу (.230)

Пять основных экранов образуют замкнутый круг в обоих направлениях.
Настройки и Диагностика в него не входят. Автоматического переключения нет.
Portable model проверяет оба перехода через границу, два полных круга
в каждом направлении и сохранение страниц для NONE/MENU.
Real LVGL host проверяет воспроизведение записанного GT911 движения
x15,y290 → x281,y271: на Home оно открывает Историю.
Это воспроизведение координат, а не новая физическая приёмка.
Live probe проверяет10 переходов по всему кругу, затем восстанавливает
исходный режим и проверяет сохранение региона.
