# Настройка Spotify

В веб-интерфейсе откройте «Обзор» → «Настройка Spotify» → «Открыть».
Используется тот же пароль панели. Язык соответствует общей настройке панели.
Client ID и точный зарегистрированный HTTPS-адрес возврата вводятся вручную.
Client Secret и пароль Spotify здесь не требуются.

В 0.115.322-dev вход недоступен до следующего этапа обработки токенов.
Наличие страницы и тестов не означает готового подключения аккаунта.
Настоящие данные и запросы Spotify в программной приёмке не используются.

После реализации обработки токенов вход открывается отдельным окном.
Если локальная страница была закрыта, на странице возврата можно выбрать
«Перенести вручную» и вставить результат в поле настройки.
Результат содержит одноразовый код: не публикуйте его.
Получение кода ещё не означает подключение; нужно подтверждение панели.
После потери ответа запрос не повторяется автоматически: проверяется статус.
Закрытие страницы не отправляет скрытую команду отмены.

## Проверка разработчиком

- `python3 tests/spotify-auth-page-static.py --help` — справка проверки.
- `python3 scripts/build-spotify-auth-assets.py --check` — соответствие flash assets.
- `python3 tests/spotify-auth-adapter-native.py` — настоящие методы C++ со
  средствами ESPHome, заменёнными только для исполнения на сервере.
- `node tests/spotify-auth-page-browser.cjs --output /tmp/spotify-page.json` —
  настоящий Chromium, три языка, ширина 320/390/1024, popup и ручной возврат,
  потерянные ответы, устаревший статус и отсутствие повторных POST.
  Страница и API обслуживаются только тестовым HTTP-сервером на loopback;
  внешние адреса перехватываются. Панель и Spotify не опрашиваются.

Для браузерной проверки нужны установленные зависимости tools/web-ui и Chromium;
PLAYWRIGHT_BROWSERS_PATH может указать существующий каталог браузера.
Генератор assets не обращается к сети. Gzip ограничен 16 КиБ, не содержит времени
создания и передаётся из flash через существующую проверку пароля и Origin.
Неподтверждённые аппаратные свойства не выдаются за результат серверных тестов.

Скрипт страницы не повторяет POST. Сам браузер может повторить отправку при
обрыве транспорта до ответа; повторное начало активного входа и повторный код
отклоняются сервером. Потерянное тело ответа проверяется отдельно от этого случая.
