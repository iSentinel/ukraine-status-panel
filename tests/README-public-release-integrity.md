# Проверки целостности публичного выпуска

Из корня проекта, в окружении с requirements-dev.txt либо CI lock:

```sh
python tests/public-release-image-native.py
python tests/public-candidate-artifact-native.py
python tests/ci-release-integrity-native.py
```

Первые два скрипта поддерживают --output artifacts/<новый-каталог> для
сохранения входов и журналов. По умолчанию временные файлы удаляются.
Проверки также включены в scripts/run-regression.sh.

public-release-image-native исполняет настоящий проверяющий скрипт и
создание архива: 16 случаев CLI, разрешённый искусственный файл и запрет
изменённого файла. Проверяются правильный SHA, обязательность файла,
профиль/версия/размер/ссылка приёмки, изменение одного байта, обрезанный,
пустой и отсутствующий файл.

public-candidate-artifact-native исполняет запись кандидата и чтение
артефакта. Новая запись не становится принятой автоматически. Неверный
числовой ID и переносы строк не попадают в GitHub Output, существующая
запись кандидата не перезаписывается.

ci-release-integrity-native проверяет исполняемые правила на разобранных
YAML и lock-файлах. Девять отрицательных изменений должны быть отклонены:
изменяемый тег Action, отсутствие хешей, старый ESPHome, неверный вид хеша,
обход проверки образа/предварительного workflow, автоматическая сборка,
пересборка при публикации и расхождение bootstrap/runtime хеша.

Все входы искусственные. Эти проверки не утверждают работу физической
прошивки, аппаратную приёмку публичного профиля или успешный запуск GitHub
Actions. Читайте docs/PUBLIC_FIRST_FLASH.md и docs/CI_DEPENDENCIES.md.
